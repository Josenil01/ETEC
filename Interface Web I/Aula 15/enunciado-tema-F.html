Contexto e Missão

A empresa de serviços IdeaLab Corp quer transformar a cultura interna: toda sugestão de melhoria vivia em papéis colados na porta do RH e sumia antes de chegar à diretoria. A caixa de sugestões física foi aposentada e o board decidiu digitalizar o processo.


Você foi designado como o Desenvolvedor Front-end responsável por criar a versão 1.0 do Mural de Sugestões Digital. O sistema deve ser uma Single Page Application (SPA) limpa e responsiva, onde qualquer colaborador possa enviar uma sugestão informando seu nome, a mensagem e a área da empresa, visualizar todas as sugestões já enviadas, editar um registro e removê-lo — tudo em uma única tela.


A arquitetura do banco de dados (PostgreSQL) já foi provisionada na nuvem pela equipe de DevOps via Neon.tech. Sua missão é construir a interface e conectá-la ao banco via API HTTP.

1
Estrutura Visual — HTML e CSS
Sem frameworks CSS · Layout com Grid ou Flexbox · 4 arquivos
20 pontos

O projeto deve ser organizado em 4 arquivos separados, cada um com responsabilidade própria:

Arquivo Responsabilidade
index.htmlEstrutura HTML da página, importação dos outros arquivos
style.cssToda a estilização em CSS puro, usando as variáveis da paleta e as 6 classes .badge-*
script_db.jsApenas a comunicação com o banco (fetch + queries SQL)
script.jsToda a lógica de interface (manipulação do DOM, eventos, toasts)

O script.js deve ser carregado no HTML como módulo ES6 (type="module") e importar as funções do script_db.js via import { ... } from './script_db.js'. Utilize a biblioteca Font Awesome 6 (CDN) para os ícones dos botões.

Layout: dois painéis lado a lado com CSS Grid (1fr 2fr no desktop). O formulário deve ter position: sticky para acompanhar o scroll da tabela.

Formulário deve conter:

  • Título dinâmico (muda entre "Nova Sugestão" e "Editar Sugestão")
  • Botão "Cancelar Edição" — visível apenas no modo edição (classe hidden para ocultar)
  • Campo oculto <input type="hidden" id="sugestao-id"> — armazena o ID durante o UPDATE
  • Campos: Seu Nome (type="text", obrigatório), Mensagem (<textarea> com rows="4", obrigatório), Área (select com opções: Atendimento, TI, RH, Infraestrutura, Comunicação, Outros)
  • Botão de submit com ícone fa-lightbulb e texto dinâmico

Tabela deve ter cabeçalho: ID · Autor/Mensagem · Área · Ações (centralizado). Botão "↻ Atualizar" no header do card da tabela, chamando a função de listagem manualmente.

No style.css, declare as 6 classes de badge (conforme especificado na seção de Paleta): .badge-atendimento, .badge-ti, .badge-rh, .badge-infra, .badge-comunicacao e .badge-outros.

🚫 Proibido: frameworks CSS (Bootstrap, Tailwind, etc.) e frameworks JS (React, Vue, etc.). CSS3 e JavaScript puro.
2
Módulo de Banco — script_db.js e SELECT
Motor central de fetch · Exportação de funções · Leitura de dados
25 pontos

No script_db.js, declare a connection string do Neon e construa o endpoint HTTP extraindo o host dela:

const DATABASE_URL = "postgresql://usuario:senha@host/banco?sslmode=require";
const host = new URL(DATABASE_URL).host;
const neonHttpEndpoint = `https://${host}/sql`;

Crie a função auxiliar central executarQueryNeon(querySQL, parametros) que encapsula todo o fetch(). Todas as outras funções CRUD devem chamá-la — nunca repetir o fetch diretamente. O header de autenticação obrigatório é:

'Neon-Connection-String': DATABASE_URL

A função deve retornar dados.rows em caso de sucesso, ou null em caso de erro (use try/catch). Erros devem ser exibidos no console.error.

Implemente e exporte a função consultarDiretoComFetch() que:

  • Executa SELECT * FROM sugestoes ORDER BY enviado_em DESC via executarQueryNeon().
  • Retorna o array de sugestões, ou [] se ocorrer erro (nunca null para a tela).

No script.js, implemente criarTabelaSugestoes() que:

  • Chama consultarDiretoComFetch() e limpa o tbody antes de renderizar.
  • Gera cada <tr> dinamicamente com: célula de ID (prefixo #), célula nome do autor + trecho da mensagem em linhas separadas, badge de área e coluna de ações.
  • A mensagem deve ser truncada para no máximo 70 caracteres na exibição da tabela: s.mensagem.length > 70 ? s.mensagem.substring(0, 70) + '…' : s.mensagem.
  • Badge colorida por área: use um objeto de mapeamento em JS para converter o valor da área na classe CSS correspondente:
const corPorArea = {
  'Atendimento':   'badge-atendimento',
  'TI':            'badge-ti',
  'RH':            'badge-rh',
  'Infraestrutura':'badge-infra',
  'Comunicação':   'badge-comunicacao',
  'Outros':        'badge-outros'
};
// uso: `badge-area ${corPorArea[s.area] || 'badge-outros'}`
  • Se não houver registros, exibir linha com colspan="4" e mensagem de estado vazio.
  • Ser chamada automaticamente ao carregar a página.
💡 Os registros retornados pelo Neon estão em dados.rows. O endpoint HTTP aceita apenas o método POST com Content-Type: application/json.
3
Envio de Sugestões — INSERT e UPDATE
Função unificada de envio · Criação e edição no mesmo formulário
25 pontos

No script_db.js, implemente e exporte as funções de escrita:

  • insertSugestao(autor, mensagem, area) — usa INSERT INTO ... RETURNING * e retorna o objeto da sugestão criada (ou null em erro). O enviado_em é gerado automaticamente pelo banco — não envie esse campo.
  • sqlAtualizarSugestao(id, autor, mensagem, area) — usa UPDATE ... SET ... WHERE id = $4 RETURNING *. A ordem dos parâmetros importa: [autor, mensagem, area, id].
// INSERT
"INSERT INTO sugestoes (autor, mensagem, area) VALUES ($1, $2, $3) RETURNING *"
params: [autor, mensagem, area]

// UPDATE
"UPDATE sugestoes SET autor = $1, mensagem = $2, area = $3 WHERE id = $4 RETURNING *"
params: [autor, mensagem, area, id]

No script.js, crie a função unificada lidarComEnvioDoFormulario(event) vinculada ao evento submit do formulário:

  • Chame event.preventDefault() para evitar recarregamento.
  • Leia o valor do <textarea> com .value.trim() para remover espaços desnecessários.
  • Leia o campo oculto sugestao-id: se preenchido → UPDATE; se vazio → INSERT.
  • Após operação bem-sucedida: chamar limparFormulario() e criarTabelaSugestoes().
  • Em caso de erro: exibir toast de erro e não limpar o formulário (permite tentar novamente).

Implemente também limparFormulario() que: chama form.reset(), limpa o campo oculto sugestao-id, restaura o título e o texto do botão, e esconde o botão "Cancelar Edição".

💡 O <textarea> é lido da mesma forma que um <input>: document.getElementById('mensagem').value. Use .trim() para evitar que espaços em branco passem como conteúdo válido.
4
UX, DELETE e Modo de Edição
Toasts · Exclusão com confirmação · prepararEdicao() · window scope
30 pontos

Toasts (notificações flutuantes):

  • Crie a função mostrarToast(mensagem, tipo) — o parâmetro tipo aceita três valores: 'success', 'error' e 'info'.
  • Cada tipo deve ter cor e ícone (Font Awesome) diferentes:
    • success → fundo --green-600, ícone fa-check-circle
    • error → fundo --rose-600, ícone fa-exclamation-triangle
    • info → fundo --blue-600, ícone fa-info-circle
  • O toast deve ser adicionado ao #toast-container (fixado no canto inferior direito da tela).
  • Deve sumir automaticamente após 3 segundos com animação de saída (opacidade + translate).
  • No CSS, implemente a animação de entrada via @keyframes slideIn e aplique com a classe toast-enter.

Função de Exclusão — DELETE:

  • No script_db.js: exporte sqlDeletarSugestao(id) com query DELETE FROM sugestoes WHERE id = $1 RETURNING *. Retorna o objeto deletado ou null.
  • No script.js: declare window.deletarSugestao = async function(id) — o window. é obrigatório pois a função é chamada via onclick inline no HTML gerado dinamicamente.
  • Exibir confirm() antes de excluir. Se o usuário cancelar, não fazer nada.
  • Após exclusão bem-sucedida: toast de sucesso + recarregar tabela.

Função de Edição — prepararEdicao():

  • Declare window.prepararEdicao = function(id, autor, mensagem, area) — também em window pelo mesmo motivo.
  • Deve preencher o campo oculto sugestao-id com o ID recebido (ativa o modo UPDATE).
  • Preencher todos os campos: nome do autor no campo de texto, mensagem completa no <textarea> (não o trecho truncado), área selecionada no <select> via .value = area.
  • Atualizar o título para "Editar Sugestão" e o texto do botão para "Salvar Edição".
  • Exibir o botão "Cancelar Edição" (remover classe hidden).

Botões de ação nas linhas da tabela:

  • Botão editar: fundo --blue-50, cor --blue-600, ícone fa-pen. No hover: fundo --blue-600, texto branco.
  • Botão excluir: fundo --red-50, cor --red-600, ícone fa-trash. No hover: fundo --red-600, texto branco.
  • Ambos os botões circulares (border-radius: 9999px), tamanho 2rem × 2rem.
  • Os onclick devem passar os dados completos da linha. Atenção: a mensagem pode conter aspas — use data-* attributes ou escape adequado: onclick="prepararEdicao(${s.id}, '${s.autor.replace(/'/g, "\\'")}', this)" passando a mensagem via atributo data-mensagem no botão para evitar quebra de string.
🎯 Atenção com aspas na mensagem: como a mensagem é um texto livre, ela pode conter aspas simples ou duplas que quebram o onclick. A solução mais robusta é armazenar a mensagem em um atributo data-mensagem no botão e recuperá-la via button.getAttribute('data-mensagem') dentro de prepararEdicao().
💡 Funções chamadas via onclick="" em HTML gerado pelo JS precisam estar no escopo global (window.nomeDaFuncao). Funções internas do módulo ES6 não são acessíveis por onclick sem isso.

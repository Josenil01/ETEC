Contexto e Missão

A coordenação pedagógica da escola técnica EduTech está cansada de lidar com listas de presença em papel: folhas que se perdem, letras ilegíveis, dados entregues com dias de atraso à secretaria e impossibilidade de consultar o histórico de frequência em tempo real.


Você foi designado como o Desenvolvedor Front-end responsável por criar a versão 1.0 do Sistema de Lista de Presença Digital. O sistema deve ser uma Single Page Application (SPA) limpa e responsiva, onde o professor possa registrar a presença de alunos informando nome e turma, consultar os registros salvos, corrigir dados equivocados e remover registros indevidos — tudo em uma única tela, sem recarregar a página.


A arquitetura do banco de dados (PostgreSQL) já foi provisionada na nuvem pela equipe de TI via Neon.tech. Sua missão é construir a interface e conectá-la ao banco via API HTTP.

1
Estrutura Visual — HTML e CSS
Sem frameworks CSS · Layout com Grid ou Flexbox · 4 arquivos
20 pontos

O projeto deve ser organizado em 4 arquivos separados, cada um com responsabilidade própria:

Arquivo Responsabilidade
index.htmlEstrutura HTML da página, importação dos outros arquivos
style.cssToda a estilização em CSS puro, usando as variáveis da paleta
script_db.jsApenas a comunicação com o banco (fetch + queries SQL)
script.jsToda a lógica de interface (manipulação do DOM, eventos, toasts)

O script.js deve ser carregado no HTML como módulo ES6 (type="module") e importar as funções do script_db.js via import { ... } from './script_db.js'. Utilize a biblioteca Font Awesome 6 (CDN) para os ícones dos botões.

Layout: dois painéis lado a lado com CSS Grid (1fr 2fr no desktop). O formulário deve ter position: sticky para acompanhar o scroll da tabela.

Formulário deve conter:

  • Título dinâmico (muda entre "Registrar Presença" e "Editar Registro")
  • Botão "Cancelar Edição" — visível apenas no modo edição (classe hidden para ocultar)
  • Campo oculto <input type="hidden" id="presenca-id"> — armazena o ID durante o UPDATE
  • Campos: Nome do Aluno (type="text", obrigatório) e Turma (select com opções: DS-1, DS-2, DS-3, ADM-1, ADM-2, RD-1)
  • Botão de submit com ícone fa-user-check e texto dinâmico

Tabela deve ter cabeçalho: ID · Aluno/Data · Turma · Ações (centralizado). Botão "↻ Atualizar" no header do card da tabela, chamando a função de listagem manualmente.

🚫 Proibido: frameworks CSS (Bootstrap, Tailwind, etc.) e frameworks JS (React, Vue, etc.). CSS3 e JavaScript puro.
2
Módulo de Banco — script_db.js e SELECT
Motor central de fetch · Exportação de funções · Leitura de dados
25 pontos

No script_db.js, declare a connection string do Neon e construa o endpoint HTTP extraindo o host dela:

const DATABASE_URL = "postgresql://usuario:senha@host/banco?sslmode=require";
const host = new URL(DATABASE_URL).host;
const neonHttpEndpoint = `https://${host}/sql`;

Crie a função auxiliar central executarQueryNeon(querySQL, parametros) que encapsula todo o fetch(). Todas as outras funções CRUD devem chamá-la — nunca repetir o fetch diretamente. O header de autenticação obrigatório é:

'Neon-Connection-String': DATABASE_URL

A função deve retornar dados.rows em caso de sucesso, ou null em caso de erro (use try/catch). Erros devem ser exibidos no console.error.

Implemente e exporte a função consultarDiretoComFetch() que:

  • Executa SELECT * FROM presencas ORDER BY data_registro DESC via executarQueryNeon().
  • Retorna o array de presenças, ou [] se ocorrer erro (nunca null para a tela).

No script.js, implemente criarTabelaPresencas() que:

  • Chama consultarDiretoComFetch() e limpa o tbody antes de renderizar.
  • Gera cada <tr> dinamicamente com: célula de ID (prefixo #), célula nome do aluno + data/hora formatada em linhas separadas, badge de turma e coluna de ações.
  • Badge de turma: classe badge-turma (fundo --blue-50, texto --indigo-700), exibindo o código da turma.
  • Data/hora formatada: new Date(p.data_registro).toLocaleString('pt-BR') — exibida abaixo do nome em cor --slate-400, tamanho menor.
  • Se não houver registros, exibir linha com colspan="4" e mensagem de estado vazio.
  • Ser chamada automaticamente ao carregar a página.
🎯 Desafio: para exibir somente as presenças do dia atual, adicione WHERE DATE(data_registro) = CURRENT_DATE ao SELECT. Essa versão filtrada também é aceita e demonstra domínio de funções de data SQL.
💡 Os registros retornados pelo Neon estão em dados.rows. O endpoint HTTP aceita apenas o método POST com Content-Type: application/json.
3
Registro de Presenças — INSERT e UPDATE
Função unificada de envio · Criação e correção no mesmo formulário
25 pontos

No script_db.js, implemente e exporte as funções de escrita:

  • insertPresenca(nome_aluno, turma) — usa INSERT INTO ... RETURNING * e retorna o objeto do registro criado (ou null em erro). O data_registro é gerado automaticamente pelo banco — não envie esse campo.
  • sqlAtualizarPresenca(id, nome_aluno, turma) — usa UPDATE ... SET ... WHERE id = $3 RETURNING *. A ordem dos parâmetros importa: [nome_aluno, turma, id].
// INSERT
"INSERT INTO presencas (nome_aluno, turma) VALUES ($1, $2) RETURNING *"
params: [nome_aluno, turma]

// UPDATE
"UPDATE presencas SET nome_aluno = $1, turma = $2 WHERE id = $3 RETURNING *"
params: [nome_aluno, turma, id]

No script.js, crie a função unificada lidarComEnvioDoFormulario(event) vinculada ao evento submit do formulário:

  • Chame event.preventDefault() para evitar recarregamento.
  • Leia o valor do campo oculto presenca-id: se estiver preenchido → é um UPDATE; se estiver vazio → é um INSERT.
  • Após operação bem-sucedida: chamar limparFormulario() e criarTabelaPresencas().
  • Em caso de erro: exibir toast de erro e não limpar o formulário (permite tentar novamente).

Implemente também limparFormulario() que: chama form.reset(), limpa o campo oculto presenca-id, restaura o título e o texto do botão, e esconde o botão "Cancelar Edição".

💡 O campo oculto é a chave: document.getElementById('presenca-id').value vazio = CREATE; preenchido = UPDATE. Note que ao editar um registro, a data_registro original é preservada — o banco não a atualiza automaticamente no UPDATE.
4
UX, DELETE e Modo de Edição
Toasts · Exclusão com confirmação · prepararEdicao() · window scope
30 pontos

Toasts (notificações flutuantes):

  • Crie a função mostrarToast(mensagem, tipo) — o parâmetro tipo aceita três valores: 'success', 'error' e 'info'.
  • Cada tipo deve ter cor e ícone (Font Awesome) diferentes:
    • success → fundo --green-600, ícone fa-check-circle
    • error → fundo --rose-600, ícone fa-exclamation-triangle
    • info → fundo --blue-600, ícone fa-info-circle
  • O toast deve ser adicionado ao #toast-container (fixado no canto inferior direito da tela).
  • Deve sumir automaticamente após 3 segundos com animação de saída (opacidade + translate).
  • No CSS, implemente a animação de entrada via @keyframes slideIn e aplique com a classe toast-enter.

Função de Exclusão — DELETE:

  • No script_db.js: exporte sqlDeletarPresenca(id) com query DELETE FROM presencas WHERE id = $1 RETURNING *. Retorna o objeto deletado ou null.
  • No script.js: declare window.deletarPresenca = async function(id) — o window. é obrigatório pois a função é chamada via onclick inline no HTML gerado dinamicamente.
  • Exibir confirm() antes de excluir. Se o usuário cancelar, não fazer nada.
  • Após exclusão bem-sucedida: toast de sucesso + recarregar tabela.

Função de Edição — prepararEdicao():

  • Declare window.prepararEdicao = function(id, nome_aluno, turma) — também em window pelo mesmo motivo.
  • Deve preencher o campo oculto presenca-id com o ID recebido (isso ativa o modo UPDATE na função de envio).
  • Preencher todos os campos do formulário com os dados da linha clicada: nome no campo de texto e turma selecionada no <select> (use selectTurma.value = turma).
  • Atualizar o título para "Editar Registro" e o texto do botão para "Salvar Correção".
  • Exibir o botão "Cancelar Edição" (remover classe hidden).

Botões de ação nas linhas da tabela:

  • Botão editar: fundo --blue-50, cor --blue-600, ícone fa-pen. No hover: fundo --blue-600, texto branco.
  • Botão excluir: fundo --red-50, cor --red-600, ícone fa-trash. No hover: fundo --red-600, texto branco.
  • Ambos os botões circulares (border-radius: 9999px), tamanho 2rem × 2rem.
  • Os onclick devem passar todos os dados da linha como argumentos: onclick="prepararEdicao(id, 'nome_aluno', 'turma')".
💡 Funções chamadas via onclick="" em HTML gerado pelo JS precisam estar no escopo global (window.nomeDaFuncao). Funções internas do módulo ES6 não são acessíveis por onclick sem isso.

Build Tools & Deploy

Você já escreveu variáveis, mexeu no DOM, buscou dados reais e guardou memória no navegador. Nesta última aula do módulo de JavaScript, o código finalmente sai do seu computador e vai pro ar, pra qualquer pessoa acessar.

1 Conceitos-Chave

Dezenas de arquivos JS/CSS separados, sem otimização, deixam um site lento. Um bundler resolve isso antes de publicar.

  • Bundling — junta vários arquivos (e seus imports, Aula 27) em poucos arquivos otimizados.
  • Minificação — remove espaços, comentários e encurta nomes, deixando o arquivo bem menor.
  • Tree-shaking — remove código que existe mas nunca é usado de verdade.
  • Vite, esbuild, Webpack — ferramentas que fazem tudo isso automaticamente. Vite é a mais popular hoje, pela velocidade.

npm run build → dist/

Rodar npm run build gera uma pasta (geralmente chamada dist/) com a versão FINAL, otimizada, pronta pra publicar. É essa pasta — não o código-fonte — que vai pro servidor de hospedagem.

Hospedagem de Conteúdo Estático

O que é "estático"

HTML/CSS/JS já prontos, sem precisar de um servidor rodando código pra cada visita (diferente de um backend em Node/PHP).

Onde publicar de graça

GitHub Pages, Netlify e Vercel pegam a pasta dist/ e colocam no ar, gratuitamente.

Deploy contínuo

Conectando o repositório Git ao serviço, cada git push atualiza o site no ar sozinho — sem subir arquivo manualmente.

Exercício 1 — O Que Vai pro dist/?

                        ⭐
                    

                    

                        

                            

                                
O que você tem

                                


meu-projeto/
├── node_modules/
├── src/
│   ├── main.js
│   └── estilo.css
├── dist/
├── .env
├── .gitignore
├── package.json
└── index.html

                                

                            

                            

                                
O que fazer

                                
Marque cada item: vai pro Git, é gerado pelo build, ou é secreto (nunca deve ser commitado)?

                            

                            

                                Dica
                                
.env costuma guardar chaves de API e senhas.

                            

                            

                                
Resposta

                                
Vai pro Git: src/, .gitignore, package.json, index.html. Gerado (não versionar): node_modules/, dist/. Secreto (nunca versionar): .env.

                            

                        

                        

                            
Resultado esperado

                            

                                Prévia
                                
.gitignore contém:
node_modules/
dist/
.env

                            

                        

                    

                


                
                

                    

                        
Exercício 2 — Ordenar os Passos do Deploy

                        ⭐⭐
                    

                    

                        

                            

                                
O que você tem (fora de ordem)

                                

                                    A) Conectar o repositório num serviço de hospedagem

                                    B) Escrever e testar o código localmente

                                    C) git push

                                    D) npm run build

                                    E) Site atualizado, no ar
                                

                            

                            

                                
O que fazer

                                
Coloque as 5 letras na ordem correta do fluxo de trabalho.

                            

                            

                                Dica
                                
A conexão com o serviço de hospedagem só precisa ser feita UMA vez, no início.

                            

                            

                                
Resposta

                                
A → B → D → C → E
(conectar hospedagem é único; depois, o ciclo B-D-C-E se repete a cada mudança — e com deploy contínuo, D e C podem ser automáticos.)

                            

                        

                        

                            
Resultado esperado

                            

                                Prévia
                                
A → B → D → C → E

                            

                        

                    

                


                
                

                    

                        
Exercício 3 — Escolha a Ferramenta pro Cenário

                        ⭐⭐⭐
                    

                    

                        

                            

                                
O que você tem

                                

                                    (1) Um portfólio pessoal simples, sem backend.

                                    (2) Um app que precisa de preview automático a cada Pull Request no GitHub.

                                    (3) Um projeto local que precisa de recarregamento instantâneo enquanto você programa.
                                

                            

                            

                                
O que fazer

                                
Combine cada cenário com: GitHub Pages, Vercel/Netlify, ou Vite.

                            

                            

                                Dica
                                
Um deles é uma ferramenta de DESENVOLVIMENTO, não de hospedagem.

                            

                            

                                
Resposta

                                
(1) GitHub Pages — simples, gratuito, direto do repositório. (2) Vercel/Netlify — geram uma URL de preview pra cada PR automaticamente. (3) Vite — é a ferramenta de build/dev, não de hospedagem; o "recarregamento instantâneo" é o Hot Module Reload dele.

                            

                        

                        

                            
Resultado esperado

                            

                                Prévia
                                
1→GitHub Pages, 2→Vercel/Netlify, 3→Vite

                            

                        

                    

                


                
                

                    

                        
Exercício 4 — Checklist Pré-Deploy

                        ⭐⭐⭐⭐
                    

                    

                        

                            

                                
O cenário

                                
Você terminou uma funcionalidade nova e está prestes a rodar git push pro repositório com deploy automático.

                            

                            

                                
O que fazer

                                
Escreva uma checklist de pelo menos 4 itens pra conferir ANTES de publicar.

                            

                            

                                Dica
                                
Pense no que você aprendeu nas Aulas 15 a 28 — o que costuma "esquecer" no código de exemplo?

                            

                            

                                
Resposta (exemplo)

                                
✔ Remover console.log de debug
✔ Rodar npm run build e testar com npm run preview localmente
✔ Conferir que não há chaves/senhas expostas no código (usar .env)
✔ Testar em telas pequenas (responsividade)
✔ Checar links e imagens quebradas

                            

                        

                        

                            
Resultado esperado

                            

                                Prévia
                                
Checklist com no mínimo 4 itens concretos e verificáveis

                            

                        

                    

                

            


            
            

                

                    
Exercício 5 — O Pipeline Completo (a Jornada Inteira)

                    ⭐⭐⭐⭐⭐
                

                

                    

                        

                            
O pedido

                            
"Adicione um botão que busca a previsão do tempo e mostra na tela." — descreva TODO o caminho, do código em branco até o usuário final ver o botão funcionando no site.

                        

                        

                            
O que fazer

                            
Escreva o pipeline completo, em passos, citando pelo menos 5 aulas diferentes do módulo (ex: "Aula 15: crio o botão e seleciono com querySelector...").

                        

                        

                            
Resposta (exemplo)

                            

                                1. Crio o botão e uso querySelector + addEventListener (Aulas 15, 22, 23).

                                2. No clique, faço fetch numa API de clima e trato erro com try/catch (Aulas 24, 25).

                                3. Organizo a lógica de busca num módulo separado, se o projeto crescer (Aula 27).

                                4. Salvo a última cidade pesquisada no localStorage, pra lembrar na próxima visita (Aula 26).

                                5. Testo tudo local com Live Server.

                                6. Rodo npm run build, confiro com npm run preview (Aula 29).

                                7. git push — o serviço de hospedagem publica a nova versão sozinho.

                                8. O botão está no ar, funcionando pra qualquer visitante do site.
                            

                        

                    

                    

                        

                            
Checklist da Jornada:

                            
✔ DOM/eventos (15, 22, 23)

                            
✔ assincronia/fetch (24, 25)

                            
✔ persistência (26) e/ou módulos (27)

                            
✔ build (29) antes do deploy

                            
✔ deploy resulta no site atualizado

                        

                        

                            
Resultado esperado

                            

                                Prévia
                                Do código em branco ao botão no ar — módulo de JavaScript concluído! 🎉

Gerenciamento de Pacotes

Nenhum projeto sério escreve tudo do zero. Hoje saímos do navegador e vamos pro terminal: npm, package.json, e como instalar (e entender) código de outras pessoas.

1 Conceitos-Chave

npm (Node Package Manager) é o gerenciador de pacotes que vem junto com o Node.js — yarn é uma alternativa popular, com os mesmos conceitos.

  • npm init -y cria um package.json novo — a "certidão de nascimento" do projeto.
  • npm install nome-do-pacote (ou npm i) baixa um pacote pra node_modules/ e anota no package.json.
  • dependencies — precisa em produção (ex: uma biblioteca de datas). devDependencies — só durante o desenvolvimento (ex: ferramenta de teste).
  • npm install nome --save-dev (ou -D) instala como devDependency.

node_modules Nunca Vai pro Git

A pasta node_modules/ pode ter dezenas de milhares de arquivos — e é 100% reconstruível rodando npm install. Ela sempre entra no .gitignore. É por isso que, ao clonar um projeto do GitHub, o primeiro passo é sempre npm install.

Scripts e Versionamento (semver)

Scripts do package.json

"scripts": { "start": "node index.js" }

Roda com npm run start (scripts especiais como start e test dispensam o run).

Semver: MAIOR.MENOR.PATCH

Ex: 2.4.1 — MAIOR muda quando quebra compatibilidade, MENOR quando adiciona algo novo sem quebrar, PATCH quando só corrige bug.

^ e ~ nas versões

^2.4.1 aceita até <3.0.0
~2.4.1 aceita até <2.5.0

Vamos testar isso ao vivo no Playground.

2. Exemplo Prático: Configurando um Projeto do Zero

Isto roda no TERMINAL, não no navegador — o preview abaixo é o que você veria ao digitar cada comando de verdade.

package.json (resultado final) 
{
  "name": "meu-projeto",
  "version": "1.0.0",
  "scripts": {
    "start": "node index.js",
    "test": "vitest"
  },
  "dependencies": {
    "date-fns": "^3.2.0"
  },
  "devDependencies": {
    "vitest": "^1.2.0"
  }
}
Terminal Prévia — não roda aqui 
$ npm init -y
Wrote to /meu-projeto/package.json

$ npm install date-fns
added 1 package in 0.8s

$ npm install --save-dev vitest
added 42 packages in 3.2s

$ npm start
> meu-projeto@1.0.0 start
> node index.js

Olá, mundo!

4. Exercícios — Gerenciando Pacotes

Estes desafios são sobre ler e escrever configuração — pratique no package.json de um projeto seu, ou só no papel/editor de texto.

Exercício 1 — Ler um package.json

⭐

O que você tem

{
  "name": "loja-online",
  "scripts": {
    "start": "node servidor.js",
    "dev": "nodemon servidor.js"
  },
  "dependencies": {
    "express": "^4.18.0",
    "dotenv": "^16.0.0"
  },
  "devDependencies": {
    "nodemon": "^3.0.0"
  }
}

O que fazer

Responda: (a) qual comando inicia o projeto em produção? (b) quantos pacotes de produção ele usa? (c) pra que serve o nodemon?

Dica

Scripts especiais como start rodam só com npm start, sem precisar de run.

Resposta

(a) npm start, que roda "node servidor.js". (b) 2 pacotes de produção: express e dotenv. (c) nodemon reinicia o servidor automaticamente quando o código muda — só útil durante o desenvolvimento, por isso é uma devDependency.

Resultado esperado

Prévia

npm start → node servidor.js

Exercício 2 — O Comando de Instalação Certo

⭐⭐

O cenário

Você quer instalar o pacote axios na versão mais recente, como dependência de PRODUÇÃO (o app usa ele em tempo real).

O que fazer

Escreva o comando npm install correto pra esse cenário.

Dica

Sem --save-dev, o npm já instala como dependency normal por padrão.

Resposta

$ npm install axios

Resultado esperado

Prévia

"axios": "^1.6.0"

Exercício 3 — Dependency ou DevDependency?

⭐⭐⭐

O que você tem

4 pacotes: express (framework de servidor), jest (roda testes automatizados), react (biblioteca de interface), eslint (aponta erros de estilo no código).

O que fazer

Classifique cada um como dependency ou devDependency, com uma frase de justificativa.

Dica

Pergunta-chave: "isso precisa existir quando o app estiver rodando pro usuário final?"

Resposta

express → dependency (o servidor precisa dele rodando). react → dependency (a interface é construída com ele). jest → devDependency (só roda testes durante o desenvolvimento). eslint → devDependency (só analisa código, não roda em produção).

Resultado esperado

Prévia

express, react → dependencies
jest, eslint → devDependencies

Exercício 4 — Escrevendo um Script

⭐⭐⭐⭐

O que você tem

{
  "name": "meu-app",
  "scripts": {
    "start": "vite"
    // seu código aqui: adicione um script "build" que roda "vite build"
  }
}

O que fazer

Adicione a chave "build" dentro de scripts, apontando pro comando vite build.

Dica

JSON não aceita comentários de verdade nem vírgula sobrando depois do último item — cuidado com a vírgula depois de "start": "vite".

Solução

{
  "name": "meu-app",
  "scripts": {
    "start": "vite",
    "build": "vite build"
  }
}

Resultado esperado

Prévia

npm run build → vite build

Exercício 5 — Resolvendo um Erro Comum

⭐⭐⭐⭐⭐

O cenário

$ git clone https://github.com/colega/projeto.git
Cloning into 'projeto'...

$ cd projeto

$ npm start
Error: Cannot find module 'express'

O que fazer

1. Explique POR QUE esse erro acontece (pense no que é e não é enviado pro GitHub).

2. Escreva o comando que resolve, e em qual pasta ele deve ser rodado.

Resposta

A pasta node_modules/ nunca vai pro Git (está no .gitignore) — só o package.json com a LISTA de dependências é versionado. Ao clonar, os pacotes ainda não foram baixados. Solução: rodar npm install dentro da pasta projeto/, que lê o package.json e baixa tudo que falta.

Checklist do Diagnóstico:

✔ identificou que node_modules não veio no clone

✔ conectou isso ao .gitignore

✔ comando certo: npm install

✔ pasta certa: dentro de projeto/

Resultado esperado

Prévia $ npm install
added 64 packages in 4.1s

$ npm start
Servidor rodando na porta 3000

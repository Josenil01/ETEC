Assincronia: O Tempo Não Para

Nem tudo no código roda na hora. Hoje aprendemos a esperar por algo sem travar a página — e simulamos um login com "demora de rede" de verdade, preparando o terreno pra Aula 25, onde vamos buscar dados reais na internet.

1 Conceitos-Chave

Algumas operações demoram — esperar um temporizador, buscar algo na internet. Assincronia é deixar essas operações rodarem "no fundo", sem travar o resto do código.

  • setTimeout(funcao, 1000) roda funcao UMA vez, depois de 1000ms.
  • setInterval(funcao, 1000) roda repetidamente — use clearInterval() pra parar.
  • Callback: o jeito antigo — passar uma função pra ser chamada quando terminar. Funciona, mas vira bagunça quando se encadeia vários.
  • Promise: o jeito moderno — representa um valor que vai existir NO FUTURO, com 3 estados: pendente, resolvida ou rejeitada.

O Código Não Espera Sozinho

setTimeout NÃO pausa o resto do código — ele só agenda algo pro futuro e o JavaScript segue em frente na mesma hora. Vamos provar isso ao vivo no Playground.

Promises e Async/Await

Criando uma Promise

new Promise((resolve, reject) => { ... })

Chame resolve(valor) quando der certo, ou reject(erro) quando der errado.

.then() e .catch()

promessa.then(r => ...).catch(e => ...)

async / await — a forma legível

const r = await promessa;

"Pausa" a função até a Promise terminar — parece código síncrono. Erros se tratam com try/catch, igual sempre.

2. Exemplo Prático: Login com Delay de Rede

Uma Promise simula uma resposta de servidor demorada — async/await + try/catch tratam sucesso e erro.

login_simulado.html 
<style>
  .painel { display: grid; gap: 10px; background: #fff; padding: 20px; border-radius: 12px; width: 280px; }
</style>

<div class="painel">
  <input id="usuario" value="Neo">
  <input id="senha" placeholder="senha (dica: 1234)">
  <button id="btn-entrar">Entrar</button>
  <p id="mensagem"></p>
</div>

<script>
  // Simula uma chamada de rede que demora 1.5s
  function fazerLogin(usuario, senha) {
    return new Promise((resolve, reject) => {
      setTimeout(() => {
        if (senha === '1234') {
          resolve(`Bem-vindo, ${usuario}!`);
        } else {
          reject('Senha incorreta.');
        }
      }, 1500);
    });
  }

  const botao = document.querySelector('#btn-entrar');
  const mensagem = document.querySelector('#mensagem');

  botao.addEventListener('click', async () => {
    mensagem.textContent = 'Carregando...';
    try {
      const resultado = await fazerLogin(
        document.querySelector('#usuario').value,
        document.querySelector('#senha').value
      );
      mensagem.textContent = resultado;
      mensagem.style.color = '#16a34a';
    } catch (erro) {
      mensagem.textContent = erro;
      mensagem.style.color = '#dc2626';
    }
  });
  </script>

Exercício 1 — setTimeout Simples

⭐

O que você tem

<button id="btn-esperar">Esperar 2 Segundos</button>
<p id="saida">--</p>

<script>
  const botao = document.querySelector('#btn-esperar');
  const saida = document.querySelector('#saida');
  // seu código aqui
</script>

O que fazer

No clique, mostre "Aguardando..." e, depois de 2000ms com setTimeout, troque para "Pronto!".

Dica

setTimeout(() => { ... }, 2000) — o segundo argumento é o tempo em milissegundos.

Solução

botao.addEventListener('click', () => {
  saida.textContent = 'Aguardando...';
  setTimeout(() => {
    saida.textContent = 'Pronto! (depois de 2 segundos)';
  }, 2000);
});

Exercício 2 — De Callback para Promise

⭐⭐

O que você tem

<button id="btn-buscar">Buscar Dado</button>
<p id="saida">--</p>

<script>
  const botao = document.querySelector('#btn-buscar');
  const saida = document.querySelector('#saida');

  // Estilo ANTIGO (callback) -- inspire-se, mas não precisa usar
  function buscarDadoComCallback(aoTerminar) {
    setTimeout(() => { aoTerminar('Dado encontrado!'); }, 1000);
  }
  // seu código aqui: crie buscarDado() devolvendo uma Promise
</script>

O que fazer

Crie buscarDado(), que devolve uma new Promise(...) resolvendo com "Dado encontrado!" depois de 1s. Chame com .then() no clique.

Dica

A função precisa de return antes do new Promise(...), senão nada é devolvido.

Solução

function buscarDado() {
  return new Promise((resolve) => {
    setTimeout(() => {
      resolve('Dado encontrado!');
    }, 1000);
  });
}

botao.addEventListener('click', () => {
  saida.textContent = 'Buscando...';
  buscarDado().then((resultado) => {
    saida.textContent = resultado;
  });
});

Exercício 3 — Encadeando .then()

⭐⭐⭐

O que você tem

<button id="btn-verificar">Verificar Pedido</button>
<p id="saida">--</p>

<script>
  const botao = document.querySelector('#btn-verificar');
  const saida = document.querySelector('#saida');

  function verificarStatus() {
    return new Promise((resolve) => {
      setTimeout(() => { resolve(3); }, 1200); // código de status
    });
  }
  const textosPorStatus = { 1: 'Pedido recebido', 2: 'Pedido em preparo', 3: 'Pedido em trânsito' };
  // seu código aqui
</script>

O que fazer

Chame verificarStatus() e encadeie DOIS .then(): o primeiro converte o código em texto (usando textosPorStatus), o segundo mostra na tela.

Dica

O que um .then() devolve vira a entrada do PRÓXIMO .then() na cadeia.

Solução

botao.addEventListener('click', () => {
  saida.textContent = 'Verificando...';
  verificarStatus()
    .then((codigo) => textosPorStatus[codigo])
    .then((texto) => {
      saida.textContent = texto;
    });
});

Resultado esperado

Prévia

Exercício 4 — Reescrevendo para Async/Await

⭐⭐⭐⭐

O que você tem (já funciona com .then)

<button id="btn-carregar">Carregar Perfil</button>
<p id="saida">--</p>

<script>
  const botao = document.querySelector('#btn-carregar');
  const saida = document.querySelector('#saida');

  function buscarPerfil() {
    return new Promise((resolve) => {
      setTimeout(() => { resolve('Perfil: Neo (Nível 99)'); }, 1000);
    });
  }

  botao.addEventListener('click', () => {
    saida.textContent = 'Carregando...';
    buscarPerfil().then((perfil) => {
      saida.textContent = perfil;
    });
  });
</script>

O que fazer

Reescreva o addEventListener usando async e await em vez de .then(), mantendo o mesmo resultado.

Dica

A função passada pro addEventListener precisa virar async () => { ... }.

Solução

botao.addEventListener('click', async () => {
  saida.textContent = 'Carregando...';
  const perfil = await buscarPerfil();
  saida.textContent = perfil;
});

Exercício 5 — Autenticação com Try/Catch

⭐⭐⭐⭐⭐

O que você tem

<input id="input-senha" placeholder="senha (dica: 1234)">
<button id="btn-entrar">Entrar</button>
<p id="saida">--</p>

<script>
  const inputSenha = document.querySelector('#input-senha');
  const botao = document.querySelector('#btn-entrar');
  const saida = document.querySelector('#saida');

  function autenticar(senha) {
    return new Promise((resolve, reject) => {
      setTimeout(() => {
        if (senha === '1234') {
          resolve('Login bem-sucedido!');
        } else {
          reject('Senha incorreta.');
        }
      }, 1200);
    });
  }
  // seu código aqui: função async com try/catch
</script>

O que fazer

1. No clique, chame autenticar(inputSenha.value) dentro de um try, usando await.

2. Se der certo, mostre o resultado em verde.

3. Se der erro, capture no catch e mostre em vermelho.

Solução

botao.addEventListener('click', async () => {
  saida.textContent = 'Verificando...';
  try {
    const resultado = await autenticar(inputSenha.value);
    saida.textContent = resultado;
    saida.style.color = '#16a34a';
  } catch (erro) {
    saida.textContent = erro;
    saida.style.color = '#f87171';
  }
});

Checklist da Autenticação:

✔ função async com await

✔ try envolve o await

✔ catch trata o reject

✔ cores diferentes pra sucesso/erro

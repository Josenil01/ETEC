Redes Básicas para VMs

Na Aula 13, uma das perguntas do assistente foi "quais portas ficam abertas?". Hoje entendemos por que essa é, talvez, a decisão de segurança mais importante ao criar uma VM.

Objetivo da Aula

Ao final desta aula, você será capaz de:

  • Diferenciar IP público de IP privado.
  • Explicar como um NSG avalia regras por prioridade.
  • Projetar regras de NSG aplicando o princípio do menor privilégio.
  • Comparar o modelo de firewall da Azure com o da AWS e do Google Cloud.

1. Conceito

IP Público

Endereço acessível de qualquer lugar da internet. Necessário se a VM precisa ser alcançada de fora (ex: um site).

IP Privado

Endereço que só existe dentro da rede virtual (Aula 13, exercício da biblioteca) — inacessível diretamente pela internet.

Rede Virtual (VNet) e Sub-Rede

Uma rede virtual isola e organiza seus recursos, definindo um intervalo de IPs privados só seu. Você pode dividi-la em sub-redes — por exemplo, uma sub-rede para VMs de aplicação e outra para banco de dados, cada uma com regras de acesso diferentes.

NSG — Network Security Group

O NSG é o "porteiro" da sua VM: um conjunto de regras de entrada e saída que permitem ou bloqueiam tráfego, com base em:

  • IP de origem/destino — de onde vem ou para onde vai o tráfego.
  • Porta — a "porta" numerada que identifica o serviço (ex: 22, 80, 443).
  • Protocolo — TCP, UDP, etc.

Cada regra tem uma prioridade (número menor = avaliada primeiro) e uma ação: Allow (permitir) ou Deny (bloquear).

2. Exemplo — As Regras do NSG da vm-loja-web

A vm-loja-web (Aula 13) tem administradores que se conectam sempre do mesmo escritório, com IP fixo 203.0.113.10. O NSG dela ficou assim:

Prioridade Porta Origem Ação
100 22 (SSH) 203.0.113.10 (só o escritório) Allow
110 80 e 443 Qualquer origem (público) Allow
200 Todas as outras Qualquer origem Deny

Isso é princípio do menor privilégio: a porta 80/443 fica aberta pra todo mundo porque é um site público — mas a porta 22 (acesso administrativo) só é liberada para o IP do escritório. Se alguém tentar acessar SSH de outro lugar do mundo, a regra de prioridade 200 bloqueia.

4. Firewall de Rede em Cada Provedor

Aqui, de novo, a estrutura muda de verdade entre provedores — não é só nome:

Azure

Network Security Group (NSG) — uma camada, anexada à sub-rede ou à VM.

AWS

Duas camadas: Security Groups (por instância, com estado) + Network ACLs (por sub-rede, sem estado).

Google Cloud

Firewall Rules definidas no nível da VPC inteira, aplicadas por "tags" de rede.

A AWS é a única com duas camadas de firewall ao mesmo tempo (Security Group + Network ACL) — um tráfego pode precisar passar pelas duas para ser permitido. Azure e Google Cloud resolvem isso com uma camada só (NSG ou Firewall Rules), embora com escopos de aplicação diferentes entre si.

5. Exercícios — Configurando o NSG

Responda no seu caderno/documento. A solução (gabarito) fica escondida.

Exercício 1 — Qual Porta?

⭐

Cenário

Diga qual porta corresponde a: (1) acessar um site em HTTPS; (2) conectar via SSH; (3) usar RDP.

Dica

Releia a tabela "Portas Comuns" da Seção 1.

Solução

(1) 443. (2) 22. (3) 3389.

Exercício 2 — Qual Regra Vence?

⭐⭐

Cenário

Um NSG tem duas regras para a porta 22: prioridade 100 = Deny para qualquer origem; prioridade 300 = Allow para o IP 203.0.113.10.

O que fazer

O IP 203.0.113.10 consegue conectar via SSH? Explique usando o conceito de prioridade.

Dica

Releia a Seção 1: "número menor = avaliada primeiro".

Solução

Não consegue. A regra de prioridade 100 (menor número, avaliada primeiro) já bloqueia qualquer origem na porta 22 antes mesmo de chegar na regra de prioridade 300 que liberaria aquele IP específico. A ordem das regras importa tanto quanto o conteúdo delas.

Exercício 3 — Duas Camadas na AWS

⭐⭐

Cenário

Explique, com suas palavras, a diferença entre Security Groups e Network ACLs na AWS, e por que isso é diferente do modelo da Azure.

Dica

Releia o box amarelo da Seção 4.

Solução

Security Groups protegem no nível da instância; Network ACLs protegem no nível da sub-rede — a AWS aplica as duas camadas em conjunto. A Azure resolve isso com uma única camada (NSG), que pode ser anexada tanto à sub-rede quanto à VM, mas sem duas camadas obrigatórias simultâneas.

Exercício 4 — IP Público ou Privado?

⭐

Cenário

Um banco de dados só deve ser acessado por outras VMs da mesma rede virtual, nunca diretamente da internet. Ele precisa de IP público?

Dica

Releia os dois cards de IP da Seção 1.

Solução

Não. Como o acesso é só de dentro da rede virtual, um IP privado é suficiente e mais seguro — não expor o banco à internet reduz a superfície de ataque.

Exercício 5 — Projete o NSG (Boss Final)

⭐⭐⭐⭐

Uma VM Windows hospeda um sistema interno acessado só pelos funcionários, que trabalham de um único escritório com IP fixo 198.51.100.5. Não é um site público.

O que fazer

Projete as regras do NSG (portas, origem, ação e uma sugestão de prioridade) para esse cenário, seguindo o princípio do menor privilégio da Seção 2.

Dica

É Windows (qual porta de acesso remoto?) e não é um site público (a porta 80/443 é necessária?).

Solução (exemplo de projeto)

Prioridade 100: porta 3389 (RDP), origem 198.51.100.5, Allow. Prioridade 200: todas as outras portas, qualquer origem, Deny. Como não é um site público, não se abre a porta 80/443 — abrir portas desnecessárias violaria o princípio do menor privilégio.

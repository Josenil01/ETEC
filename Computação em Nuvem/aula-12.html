Máquinas Virtuais: Conceitos

Começa o maior módulo do curso. Antes de criar uma VM de verdade (Aula 13), vamos entender as duas decisões que você toma toda vez: qual imagem e qual tamanho.

Objetivo da Aula

Ao final desta aula, você será capaz de:

  • Diferenciar imagem de tamanho (SKU) de uma VM.
  • Escolher a família de tamanho (B/D/E/F/N) certa para uma carga de trabalho.
  • Decodificar o nome de uma VM, ex: Standard_D2s_v5.
  • Reconhecer o mesmo conceito de tamanho na AWS e no Google Cloud.

1. Conceito

Uma máquina virtual (VM) é o produto IaaS clássico (Aula 5): um servidor virtualizado (Aula 2) onde você controla o sistema operacional e o software instalado, exatamente como um computador físico. Toda VM nasce de duas escolhas:

Imagem

Um template que já inclui um sistema operacional (e às vezes ferramentas prontas, como um servidor web). Escolher a imagem certa evita instalar tudo do zero.

Tamanho (Size / SKU)

A combinação de vCPUs, RAM, disco e rede que a VM vai ter — organizada em famílias, cada uma pensada para um tipo de carga de trabalho.

Famílias de Tamanho na Azure

Decodificando o Nome: Standard_D2s_v5
D 2 s v5

D = família (propósito geral)

2 = número de vCPUs

s = suporta disco Premium SSD

v5 = geração de hardware

Escala e Resiliência (prévia da Aula 15)

Conjuntos de escala (scale sets) — grupos de VMs idênticas com balanceamento de carga, que crescem/encolhem automaticamente (elasticidade, Aula 2). Aprofundamos na Aula 15.

Conjuntos de disponibilidade (availability sets) — agrupam VMs por domínio de atualização e domínio de falha, reduzindo a chance de todas caírem numa mesma manutenção ou falha de hardware. Complementa (mas não substitui) as zonas de disponibilidade da Aula 6.

2. Exemplo — Qual VM a TechBox Escolhe?

A TechBox (Aula 2) precisa de duas VMs diferentes, com escolhas bem diferentes:

VM de testes

Imagem: Ubuntu Server. Tamanho: Standard_B2s (B-series, barata, usada só em horário comercial — Aula 10).

VM do site em produção

Imagem: Ubuntu Server com o servidor web pré-configurado. Tamanho: Standard_D2s_v5 (D-series, propósito geral, aguenta tráfego constante).

Usar uma B-series barata em produção economizaria dinheiro, mas arriscaria desempenho no pico de acessos; usar uma D-series nos testes seria pagar mais caro por algo que não precisa de tanta força. A escolha certa depende sempre da carga de trabalho real.

5. Exercícios — Escolhendo a VM Certa

Responda no seu caderno/documento. A solução (gabarito) fica escondida.

Exercício 1 — Decodifique o Nome

⭐

Cenário

Uma VM se chama Standard_F4s_v2. Identifique: família, número de vCPUs, e se suporta disco Premium SSD.

Dica

Releia o diagrama "Decodificando o Nome" da Seção 1 e aplique a mesma lógica.

Solução

Família: F (otimizada para CPU). vCPUs: 4. Suporta Premium SSD: sim (letra "s"). Geração de hardware: v2.

Exercício 2 — Família Certa Para Cada Carga

⭐⭐

Cenário

Indique a família mais adequada (B, D, E ou N) para cada carga de trabalho:

  1. Treinar um modelo de reconhecimento de imagens.
  2. Um banco de dados que mantém tudo em memória para respostas rápidas.
  3. Uma VM de estudos, ligada só algumas horas por semana.
Dica

Releia a tabela de famílias da Seção 1.

Solução

  1. N-series (GPU)
  2. E-series (memória)
  3. B-series (burstable/econômica)

Exercício 3 — Traduza Entre Provedores

⭐

Cenário

Um colega usa uma instância c5.large na AWS. Que tipo de carga de trabalho isso sugere? Qual seria a família equivalente na Azure e no Google Cloud?

Dica

Releia a Seção 4 — o "c" tem um significado específico.

Solução

"c" = otimizada para CPU. Equivalentes: F-series na Azure, c2 no Google Cloud.

Exercício 4 — Imagem ou Tamanho?

⭐

Cenário

Diga se cada escolha é sobre imagem ou tamanho: (1) "Ubuntu Server 22.04"; (2) "4 vCPUs, 16 GB de RAM".

Dica

Um define o sistema operacional; o outro define a capacidade de hardware.

Solução

(1) Imagem. (2) Tamanho.

Exercício 5 — Parecer Técnico (Boss Final)

⭐⭐⭐⭐

Uma faculdade quer uma VM para rodar um sistema de biblioteca (baixo uso, poucos acessos simultâneos, orçamento apertado) e outra VM para processar grandes volumes de dados de pesquisa científica (uso intenso de CPU por horas seguidas).

O que fazer

Recomende uma família (B, D, E, F ou N) para cada uma das duas VMs, com 1 justificativa cada.

Dica

"Orçamento apertado + baixo uso" e "uso intenso de CPU" são as duas pistas centrais.

Solução (exemplo de parecer)

Sistema de biblioteca: B-series — carga leve e esporádica, a natureza burstable e econômica evita pagar por capacidade ociosa (Aula 3/10). Processamento de dados de pesquisa: F-series — uso intenso e sustentado de CPU é exatamente o perfil que essa família otimiza.

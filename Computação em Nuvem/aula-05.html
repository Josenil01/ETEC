Modelos de Serviço

Na Aula 4 vimos onde a nuvem pode rodar. Hoje vemos quanto dela você mesmo precisa gerenciar — de "alugo só o hardware" até "só uso o app pronto".

Objetivo da Aula

Ao final desta aula, você será capaz de:

  • Diferenciar IaaS, PaaS, SaaS e FaaS.
  • Identificar quem gerencia cada camada em cada modelo.
  • Escolher o modelo de serviço certo para um cenário dado.
  • Reconhecer um produto real de cada modelo em cada provedor.

1. Conceito

IaaS Infrastructure as a Service

O provedor entrega o hardware virtualizado (VM, rede, disco). Você instala e cuida do sistema operacional, runtime e aplicação pra cima.

Exemplos: Amazon EC2, Azure Virtual Machines, Google Compute Engine.

PaaS Platform as a Service

O provedor cuida do sistema operacional e do ambiente de execução (runtime). Você só entrega o código da sua aplicação.

Exemplos: Azure App Service, AWS Elastic Beanstalk, Google App Engine.

SaaS Software as a Service

O provedor cuida de tudo, incluindo a própria aplicação. Você só usa, geralmente pelo navegador.

Exemplos: Microsoft 365, Gmail, Google Workspace, Salesforce.

FaaS Function as a Service / Serverless

Você entrega só uma função (um pedaço de código). O provedor liga o ambiente na hora que a função é chamada e desliga logo depois — você paga só pelas execuções.

Exemplos: AWS Lambda, Azure Functions, Google Cloud Functions. Vamos praticar isso de verdade no Módulo 3 (Aulas 20-21).

Quem cuida de cada camada? (visão simplificada)
Camada On-Premise IaaS PaaS SaaS
Aplicação e dados Você Você Você Provedor
Runtime / ambiente Você Você Provedor Provedor
Sistema operacional Você Você Provedor Provedor
Virtualização, servidores, rede, datacenter Você Provedor Provedor Provedor

O que é cada camada?

Aplicação e dados

O próprio programa que você usa ou desenvolveu (o site, o app, o sistema) e as informações que ele guarda (cadastros, pedidos, arquivos). É a camada mais "visível" — o motivo pelo qual o sistema existe.

Runtime / ambiente

O "motor" que executa o código da aplicação — ex: Node.js, .NET, Python, Java. Inclui bibliotecas e dependências necessárias para o programa rodar. Sem o runtime certo instalado e configurado, o código não executa.

Sistema operacional

O software base da máquina (Windows Server, Linux/Ubuntu, etc.) que gerencia arquivos, processos e permissões. Alguém precisa instalar, atualizar e aplicar patches de segurança nele.

Virtualização, servidores, rede, datacenter

A camada mais "de baixo": o hipervisor que cria as VMs (Aula 2), os servidores físicos, os cabos/roteadores de rede e o próprio prédio do datacenter (energia, refrigeração, segurança física). É a base sobre a qual tudo o resto roda.

Essa tabela é uma prévia — vamos formalizar a matriz de responsabilidade compartilhada completa (incluindo segurança) na Aula 6.

2. Exemplo — Pizza as a Service

A analogia clássica (e a mais fácil de lembrar) usa pizza. Pensando em fazer uma pizza para comer hoje à noite:

On-premise = "Faço em casa"

Você compra o forno, a mesa, os ingredientes, e faz tudo do zero. Controle total, trabalho total.

IaaS = "Uso a cozinha industrial alugada"

Alguém já tem o forno, a bancada, o gás — você ainda faz a massa e escolhe os ingredientes, mas não precisa comprar equipamento.

PaaS = "Peço a massa pronta"

A massa já vem pronta e assada na medida certa — você só escolhe e coloca o recheio (sua aplicação).

SaaS = "Peço a pizza pronta"

Chega pronta na porta. Você só come — nem sabe (nem precisa saber) como foi feita.

FaaS = "Pago só pela fatia que como"

Em vez de manter uma pizzaria pronta o tempo todo (mesmo de madrugada, sem clientes), o forno só liga quando alguém pede uma fatia, assa aquela fatia, entrega e desliga. Ninguém paga por um forno aceso à toa.

5. Exercícios — IaaS, PaaS, SaaS ou FaaS?

Responda no seu caderno/documento. A solução (gabarito) fica escondida.

Exercício 1 — Classifique o Serviço

⭐

Cenário

Classifique cada produto como IaaS, PaaS, SaaS ou FaaS:

  1. Microsoft 365 (Word, Excel online)
  2. Uma VM Linux crua na Google Compute Engine, onde você mesmo instala tudo
  3. Azure App Service, onde você só envia o código do seu site
  4. Uma função no AWS Lambda que roda só quando chega um pedido novo
Dica

Pergunte: "eu preciso instalar o sistema operacional? preciso configurar o runtime? ou só uso um app pronto?"

Solução

  1. SaaS — aplicação pronta, só usa.
  2. IaaS — hardware virtualizado cru, você instala tudo em cima.
  3. PaaS — só entrega código, o runtime já existe.
  4. FaaS — só uma função, executada sob demanda.

Exercício 2 — Complete a Pizza

⭐

Cenário

Complete: "___(1)___ é como fazer a pizza em casa. ___(2)___ é como alugar a cozinha industrial. ___(3)___ é pedir a massa pronta. ___(4)___ é pedir a pizza pronta na porta."

Dica

Releia a Seção 2.

Solução

(1) On-premise — (2) IaaS — (3) PaaS — (4) SaaS.

Exercício 3 — Escolha o Modelo Certo

⭐⭐

Cenário

Um desenvolvedor quer publicar um site em Node.js rapidamente, sem se preocupar em configurar servidor, sistema operacional ou runtime — só quer subir o código e ver funcionando.

O que fazer

Qual modelo de serviço é mais adequado? Por que não IaaS?

Dica

Ele já disse que não quer configurar nada abaixo do código — isso elimina uma opção da tabela da Seção 1.

Solução

PaaS — o runtime e o sistema operacional já vêm prontos, o desenvolvedor só entrega o código. IaaS exigiria que ele mesmo instalasse e configurasse o Node.js e o sistema operacional na VM, o que ele explicitamente não quer fazer.

Exercício 4 — Qual Provedor, Qual Produto?

⭐

Cenário

Complete a tabela: qual é o produto PaaS da AWS? E o produto IaaS do Google Cloud?

Dica

Releia a tabela da Seção 4.

Solução

PaaS na AWS: Elastic Beanstalk. IaaS no Google Cloud: Compute Engine.

Exercício 5 — Parecer Técnico (Boss Final)

⭐⭐⭐⭐

Uma pequena empresa de contabilidade quer parar de usar planilhas soltas e adotar um sistema de gestão financeira. Ela não tem nenhum desenvolvedor no time, só quer "abrir e usar".

O que fazer

Recomende um modelo de serviço (IaaS, PaaS, SaaS ou FaaS) para essa empresa, com pelo menos 2 argumentos. Depois, explique por que os outros 3 modelos seriam piores escolhas para esse caso específico (não para casos em geral).

Dica

"Não tem nenhum desenvolvedor no time" é a pista mais importante desse cenário.

Solução (exemplo de parecer)

Recomendo SaaS (ex: um sistema de contabilidade já pronto, tipo um ERP em nuvem). Argumentos: (1) a empresa não tem desenvolvedor para escrever código nem para administrar servidor, e SaaS não exige nenhum dos dois; (2) o sistema já vem pronto e testado, reduzindo risco de erro numa área sensível como finanças. IaaS e PaaS exigiriam contratar ou terceirizar desenvolvimento (algo que ela não tem/não quer), e FaaS não faz sentido aqui porque não é um sistema completo de gestão, é só um modelo para rodar pedaços de código sob demanda — não substitui um software pronto de uso direto.

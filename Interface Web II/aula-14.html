Aula 14: Arquitetura em Camadas

Até agora, o nosso login só existia dentro do navegador. Vamos entender a arquitetura Cliente / Servidor / Base de Dados e dar o primeiro passo para um servidor.js real, com Node.js e Express.

1. O Servidor (Back-End)

Até agora, todo o nosso JavaScript correu no Navegador (Front-End). O código do navegador é rápido e interativo, mas fica totalmente exposto a quem inspecionar a página — não dá para confiar nele para guardar senhas ou validar credenciais de verdade.

Para processar regras de negócio críticas — como verificar se um e-mail e senha realmente pertencem a um utilizador — e aceder à Base de Dados, precisamos de um ambiente seguro, longe do navegador. Esse ambiente é o Servidor Web (Back-End). Tecnologias como o Node.js permitem-nos usar o mesmo JavaScript do lado do servidor, criando a verdadeira arquitetura em camadas de uma aplicação Web.

2. A Arquitetura em Camadas

1. Cliente / Navegador

Onde o utilizador vê e preenche o formulário de login. Responsável por mostrar a interface gráfica e capturar os cliques.

Tecnologias:

HTML, CSS, JS (React, Vue)

2. Servidor Web (App)

A base central. Recebe os pedidos via HTTP, verifica as credenciais recebidas e toma as decisões de segurança.

Tecnologias:

Node.js (Express), Python, PHP

3. Base de Dados

Onde os utilizadores registados ficam guardados de verdade. A memória permanente do sistema, lida e escrita com segurança.

Tecnologias:

PostgreSQL (Neon.tech) — chegamos lá na Aula 19

3. Setup Local (Preparando o Ambiente)

Antes de colocar o nosso servidor no ar, precisamos instalar as peças fundamentais no computador. Abra o terminal (linha de comandos) na pasta do projeto e execute as seguintes ordens:

npm init -y
O Manifesto (Inicializar Projeto) Cria o ficheiro package.json. É o registo oficial do projeto, onde ficam guardadas as informações de todas as bibliotecas que o nosso servidor vai usar.
npm install express
O Framework (Express.js) Instala o framework Express. É a ferramenta mais famosa do Node.js para criar servidores Web, pois facilita a criação das "rotas" (ex: /api/login) que vão ouvir os pedidos HTTP do Cliente (Front-End).
npm install cors
Liberação de Acesso entre Portas (CORS) Instala o CORS (Cross-Origin Resource Sharing). Sem isto, o Navegador (que corre na porta 5500 do Live Server) bloqueia o Front-End de comunicar com o nosso servidor (na porta 3000) por segurança. O CORS autoriza essa partilha local.

* Aviso importante: para que o comando "npm" funcione, é obrigatório ter o Node.js instalado no seu sistema operativo.

Camada 1 (Front-End) 1. No ficheiro cliente.js (O Navegador)

Em vez de apontar a transmissão para um domínio na internet (http://api-do-projeto.com/...), você aponta para a sua própria máquina (localhost) na "porta" específica onde o servidor está a ouvir (por exemplo, a porta 3000). O seu fetch ficaria assim:

cliente.js
const form = document.getElementById('login-form');
const output = document.getElementById('login-output');

form.addEventListener('submit', async (event) => {
    event.preventDefault(); // Impede o recarregamento

    const email = document.getElementById('input-email').value;
    const senha = document.getElementById('input-senha').value;
    output.innerHTML = '<div class="loader"></div> Conectando ao Servidor Local...';

    // O Cliente chama o Servidor na própria máquina (localhost) na porta 3000
    const resposta = await fetch('http://localhost:3000/api/login', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ email, senha })
    });

    const dados = await resposta.json();
    output.innerHTML = `> STATUS: <strong>${dados.mensagem}</strong>`;
});

Camada 2 (Back-End) 2. No ficheiro servidor.js (O Node.js)

No código do servidor, precisamos de adicionar um guarda de fronteira chamado CORS (Cross-Origin Resource Sharing).

Porquê? Por questões de segurança, os navegadores bloqueiam um site (que está a correr no Live Server, por exemplo, na porta 5500) de fazer pedidos para um servidor noutra porta (a porta 3000). Para permitir essa conversa local, o servidor Node.js tem de usar a biblioteca cors.

O código do servidor local seria assim:

servidor.js (Ficheiro Node.js/Express)
const express = require('express');
const cors = require('cors'); // 1. Importar o CORS

const app = express();

// 2. Avisar o servidor para permitir chamadas locais (ignorar o bloqueio do navegador)
app.use(cors());
app.use(express.json());

// 3. A nossa rota de login
app.post('/api/login', (req, res) => {
    const { email, senha } = req.body;

    // ... aqui entraria a verificação na base de dados (Aula 19) ...

    res.json({ mensagem: 'Resposta do meu servidor local!' });
});

// 4. O servidor fica à escuta na porta 3000 do seu computador
app.listen(3000, () => console.log('Servidor local online em http://localhost:3000'));

5. Perguntas de Fixação

Nível: Fácil

01

Identificação de Camadas: Se uma regra de negócio disser "A senha do utilizador deve ser encriptada antes de guardada na base de dados", essa lógica deve ser escrita no ficheiro cliente.js (Navegador) ou no servidor.js (Node.js)? Porquê?

Nível: Médio

02

Dissecando o Node.js: Observe o código do servidor.js da Etapa 3. O comando app.post('/api/login', ...) define o quê exatamente? Que função desempenham os objetos req (Request/Pedido) e res (Response/Resposta)?

Nível: Desafio

03

Conectando as Peças: No cliente.js nós enviamos um objeto JSON com as propriedades { email: "ana@email.com", senha: "1234abcd" } usando o fetch.

Descreva exatamente a linha de código no servidor.js responsável por extrair esses dois valores de dentro da mensagem recebida, para depois usá-los na verificação da lista de utilizadores.
